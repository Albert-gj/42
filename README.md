Основные задачи, которые решает Git:

Хранение истории изменений. Git сохраняет не просто разницу между файлами, а полную слепок (snapshot) состояния проекта на каждый момент фиксации. Это позволяет в любой момент посмотреть, как проект выглядел вчера, месяц или год назад, и точно узнать, кто, когда и какие именно строки кода изменил.
Возможность отката (Revert и Reset). Если в код закралась ошибка или был удалён важный фрагмент, можно мгновенно вернуться к любой предыдущей стабильной версии. Это работает как "машина времени" для проекта.
Параллельная разработка. Git позволяет нескольким программистам одновременно работать над одним и тем же проектом, не опасаясь случайно перезаписать изменения друг друга.
Объединение кода (слияние — Merge, и перемещение — Rebase). Когда разработчики заканчивают свои задачи, Git помогает автоматически или полуавтоматически объединить их наработки в единую версию проекта, подсвечивая места, где изменения конфликтуют.
Распределённость. В отличие от старых централизованных систем (например, SVN), у каждого разработчика на компьютере хранится полная копия всего репозитория (хранилища) со всей историей. Можно работать (создавать коммиты, просматривать историю) даже без интернета, а затем синхронизировать изменения с общим сервером.
Создание тегов (Tags). Маркировка важных точек в истории проекта, например, версий для релиза (v1.0.0, v2.1.5).
Временное сохранение изменений (Stashing). Позволяет спрятать незавершённые правки, переключиться на другую задачу (например, срочно исправить баг), а затем вернуться к ним.

Что такое коммит (commit)

Коммит — это сохранённая точка в истории проекта. Его можно сравнить с контрольной точкой в видеоигре или с очень подробным, осмысленным сохранением.

Когда разработчик завершает логически завершённый этап работы (например, исправил одну ошибку или добавил одну новую кнопку), он делает коммит. Каждый коммит состоит из:

уникального идентификатора (хэша) — длинной строки символов (например, a1b2c3d), которая служит его паспортом;
снимка состояния файлов — Git сохраняет текущее состояние всех отслеживаемых файлов;
ссылки на родительский коммит — так выстраивается непрерывная цепочка истории;
метаданных — имени автора, даты и времени создания;
сообщения коммита — краткого описания того, что было сделано (например, "Исправлен вылет приложения при пустом имени пользователя"). Хорошая практика — писать сообщения в императивном стиле ("Добавить валидацию", а не "Добавил валидацию").

Коммиты — это фундамент работы в Git. Они позволяют разбивать большую задачу на маленькие, проверяемые шаги.

Что такое ветка (branch)

Ветка — это независимая линия разработки, указатель на один из коммитов. По умолчанию в каждом репозитории есть главная ветка (обычно она называется main или master). Она содержит стабильную, рабочую версию продукта.

Представьте себе ствол дерева. main — это его основной ствол. Когда нужно добавить новую функцию, разработчик не делает этого прямо в стволе, а создаёт от него новую ветку.
